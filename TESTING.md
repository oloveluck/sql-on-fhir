# Testing sql-on-fhir

## Results

| Suite | What it checks | Result |
|---|---|---|
| The shared SQL on FHIR test suite (from FHIR/sql-on-fhir.js, `tests/vendor/sql-on-fhir-tests`) | each test's view over its resources gives its expected rows (as a multiset, columns in order where the test says so); a view the test calls invalid is rejected | 144/144 |
| The guide (`tests/guide-test.rkt`) | every view in guide.md parses strictly; the worked example and cheat sheet give the rows the text states; the common problems behave as written | passes |
| The manual (`tests/docs-test.rkt`) | scribblings/sql-on-fhir.scrbl renders with no broken reference to its own sections or bindings | passes |
| The generated model | the files under `model/` equal a fresh generation from `spec/` | `raco sql-on-fhir check` |

## Where the model and the suite come from

| What | From | How |
|---|---|---|
| the model (`ViewDefinition`, `#lang sql-on-fhir`, required-binding checks) | `spec/hl7.fhir.uv.sql-on-fhir.tgz`: 3.0.0-ballot, published to the FHIR registry from HL7's [FHIR/sql-on-fhir-v2](https://github.com/FHIR/sql-on-fhir-v2) | generated by the fhir package's codegen (`target.rkt`) |
| the operations' definitions (`$sql-run`, `$sql-export`) | the same package's OperationDefinitions | generated as data (`model/operations.rkt`) |
| the test suite | the shared suite from [FHIR/sql-on-fhir.js](https://github.com/FHIR/sql-on-fhir.js), at the commit in its `SOURCE.txt` | vendored verbatim |

The vendored copies are byte-identical to what `raco sql-on-fhir fetch` pulls.

## Running them

```sh
raco test .                     # unit tests and the shared suite
raco sql-on-fhir tck [-v]       # the shared suite with its report (floor 144)
raco sql-on-fhir check          # the generated model is up to date with spec/
raco sql-on-fhir regen          # regenerate the model
raco sql-on-fhir fetch [--version V] [--tests-commit SHA]   # pull the IG package and the suite again
```
