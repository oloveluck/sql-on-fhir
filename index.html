sql-on-fhir: SQL on FHIR for Racket🔗

SQL on FHIR for Racket. You write a ViewDefinition, a flat table over one resource type with a FHIRPath per column, in a .sof file; raco sql-on-fhir run evaluates it over a directory of resources and prints rows. The ViewDefinition model is generated from HL7’s published package, so a view is checked against the IG’s own model when it compiles, and the IG’s $sql-run and $sql-export operations are provided. The shared test suite passes, 144 of 144. Part of the fhir family.

1 Quick start🔗

1. Install. The packages are not on the Racket package server yet; clone the repositories side by side and install from source:

raco pkg install --link --auto fhir/fhir fhir/fhir-spec fhirpath sql-on-fhir

2. Write a view.

#lang sql-on-fhir

(ViewDefinition

 (name "bp_readings") (status "active") (resource "Observation")

 (where (ViewDefinitionWhere (path "code.coding.where(system = 'http://loinc.org').code = '85354-9'")))

 (select (ViewDefinitionSelect

          (column (ViewDefinitionSelectColumn (name "patient") (path "subject.getReferenceKey(Patient)"))

                  (ViewDefinitionSelectColumn (name "date") (path "effective.ofType(dateTime)"))

                  (ViewDefinitionSelectColumn (name "systolic")

                    (path "component.where(code.coding.code = '8480-6').value.ofType(Quantity).value"))))))

3. Run it over a directory of resources.

$ raco sql-on-fhir run readings.sof patients/ --format csv

patient,date,systolic

p1,2024-03-01T09:00:00Z,152

p1,2024-04-02T09:30:00Z,138

A misspelled element, a wrong type or a status outside its value set is a compile error on the form.

2 Writing a view🔗

A ViewDefinition picks a resource type, filters it (where) and selects columns, each a FHIRPath path. The forms are the IG’s elements in the fhir/r6 form syntax: ViewDefinition, ViewDefinitionWhere, ViewDefinitionSelect (column, nested select, forEach, forEachOrNull, repeat, unionAll), ViewDefinitionSelectColumn (path, name, description, collection, type, tag) and ViewDefinitionConstant (a %name for paths). Paths may use getResourceKey(), getReferenceKey(Type), %rowIndex and the view’s constants. The reference is the SQL on FHIR IG.

3 Using it🔗

3.1 Command line🔗

raco sql-on-fhir run view.sof data/ [–format ndjson|json|csv|fhir]

  

a view (a module or JSON) over a directory, Bundle or resource

raco sql-on-fhir tck [-v]

  

the shared suite (floor 144)

raco sql-on-fhir regen | check

  

regenerate the model from spec/; verify it is current

raco sql-on-fhir fetch [–version v] [–tests-commit sha]

  

refresh the package and the suite

Exit codes: 0, 1 on an error or a suite regression, 2 on usage.

3.2 As a module🔗

(require "readings.sof") gives resources (typed nodes), (->nodes) and (->json) (the ViewDefinitions as JSON). racket readings.sof prints the JSON.

(require (only-in "readings.sof" [->json views])
         fhir/data-source (only-in sql-on-fhir/operations view-rows))
(parameterize ([current-data-source (resources->data-source observations)])
  (view-rows (car (views))))         ; a list of hashes, one per reading

3.3 As an operation🔗

$sql-run answers the IG’s formats as a Binary (or rows as a Parameters); data comes from current-data-source or #:resource inputs. fhir-server serves the same values over HTTP with (serve-operations (list $sql-run $sql-export) #:port 8080).

(require fhir/operation fhir/data-source sql-on-fhir/operations)
(parameterize ([current-data-source (directory->data-source "patients/")])
  ($sql-run view #:_format "csv")                       ; the view is the subject
  (apply-operation "$sql-run" #:subjectCanonical "http://example.org/ViewDefinition/x" #:_format "fhir"))

4 Limits🔗

  • No SQL database: views are evaluated in memory through the fhirpath engine, one row list per view.

  • $sql-run ignores parameters, context, group and source; a patient that does not resolve filters to nothing; only ViewDefinition subjects (no SQLQuery or SQLView Libraries); no Parquet.

  • $sql-export completes synchronously, with the results inline as Binaries: no job, polling, cancellation or download urls; _format=fhir becomes ndjson.

  • A column’s type and tag are not enforced; constants must be primitives; getReferenceKey() expects relative Type/id references.

(eval-view view resources) → (listof list?)

  view : fhir?
  resources : (listof fhir?)
The rows of a typed ViewDefinition over typed resources, each row an association list from column name to value, in column order. Every path goes through the fhirpath engine; a view error is raised by 'eval-view.

(view-columns view) → (listof symbol?)

The column names, in declaration order.

sql-on-fhir/operations🔗

 (require sql-on-fhir/operations) package: sql-on-fhir

value

$sql-run : procedure?

On the IG’s SQLRun definition, registered when the module loads. The view is the subject (subjectResource), or named by #:subjectCanonical or #:subjectReference from the data source. Data: #:resource inputs (Bundles unwrapped) or the data source, filtered by #:patient and #:_since; #:_limit. #:_format is "ndjson" (the default), "json" or "csv" (with #:header) as a Binary, or "fhir" as a Parameters of rows.

value

$sql-export : procedure?

#:subject is a list of views, references or canonicals; completes synchronously with a manifest Parameters: one output per subject, its result a Binary.

procedure

(view-rows view [resources]) → (listof hash?)

  view : hash?
  resources : (or/c (listof hash?) #f) = #f
Rows as hashes for a ViewDefinition given as JSON (strictly parsed); resources default to the data source’s.
